# Young Analysts — Capstone Portfolio Framework

## Portfolio principle
The portfolio is evidence of what a learner can do. It is not a public profile, leaderboard, or collection of participation badges.

## Builder capstone
**Question:** Can I build a small, testable digital/data solution?
Required evidence:
- problem statement;
- safe inputs;
- working Python or spreadsheet artefact;
- at least 3 tests;
- short explanation;
- one improvement after testing.
Review focus: correctness, testing habit, clarity, safe data use.

## Analyst capstone
**Question:** Can I turn data into a defensible finding?
Required evidence:
- analytical/research question;
- synthetic or approved dataset;
- cleaning/quality log;
- calculated summaries;
- at least 2 purposeful visualisations;
- interpretation;
- limitation;
- reproducibility note.
Review focus: denominators, data quality, statistical reasoning, evidence/interpretation separation.

## Innovator capstone
**Question:** Can I use evidence to support a proportionate decision?
Required evidence:
- analysis charter;
- source and governance note;
- reproducible workflow;
- verification/testing log;
- decision brief;
- alternative explanation;
- recommendation;
- next evidence need;
- presentation and response to questions.
If AI is used: prompt/use disclosure, verification log and human changes are mandatory.

## Moderation
For pilot cohorts, instructors should double-mark a sample of portfolios and compare rubric decisions. Discuss disagreements by criterion rather than averaging unexplained scores. Preserve rubric version with the evidence.

## Showcase boundary
Only work explicitly cleared for showcase should leave the private learning environment. Remove unnecessary personal data and prefer synthetic/project data. Learner participation in a showcase should not be a prerequisite for competency.
