# Young Analysts — Assessment Blueprint

This blueprint prevents the programme from becoming a collection of easy recall quizzes.

## Minimum evidence per six-module track
- 18 scored selected-response items: at least 3 calculation/predict, 3 interpretation, 3 debug/diagnosis, 3 test-design, 3 responsible-practice, and no more than 6 pure concept items.
- 6 module performance tasks.
- 1 integrated capstone.
- At least 2 instructor-reviewed explanations where the learner must distinguish evidence from interpretation.
- At least 1 privacy/ethics decision and 1 limitations statement.

## Cognitive distribution
Target distribution across a track:
- Recall/recognise: 15–20%
- Apply/calculate: 25–30%
- Diagnose/debug: 20–25%
- Interpret/evaluate: 20–25%
- Design/create: demonstrated primarily through performance tasks.

## Item-writing controls
1. Test one primary construct per selected-response item.
2. Wrong options must be plausible misconceptions.
3. Avoid clues from option length or grammar.
4. Do not make “always/never” the routine giveaway.
5. Numerical items retain units and denominators.
6. Interpretation items specify the evidence actually available.
7. AI items never treat model output as evidence merely because it is fluent.
8. Research/statistics items distinguish sample evidence from population claims.
9. Rotate correct-option positions during final assembly.
10. Record rationale and intended misconception for each item.

## Performance-task evidence record
Each submission should eventually store:
- task and version;
- artefact;
- dataset/source version;
- test/QA evidence;
- learner explanation;
- limitation/reflection;
- rubric scores by dimension;
- instructor feedback;
- resubmission status.

## Mastery logic
Do not calculate competency from quiz percentage alone.
Suggested pilot logic:
- selected-response knowledge check >= 70%;
- performance task >= 8/12;
- Responsible Practice > 0;
- required evidence fields complete.
Module status: NOT STARTED → LEARNING → EVIDENCE SUBMITTED → REVISION NEEDED / COMPETENT.
Track completion requires all module competencies plus capstone review.

## Validation metrics after pilot
Analyse item difficulty, option selection, missingness, completion time, task failure modes and rubric agreement. Flag items that nearly everyone gets right/wrong, distractors never selected, ambiguous wording, or tasks where technical friction overwhelms the intended construct.

No cut score should be described as externally validated until sufficient pilot evidence supports that claim.
